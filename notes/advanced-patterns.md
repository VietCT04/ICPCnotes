# Advanced Competitive Programming Patterns

This note collects reusable ideas from a sequence of Codeforces problems. The goal is not to memorize each solution, but to recognize the modeling pattern that makes the problem small, mergeable, or reducible to a standard algorithm.

## 1. Non-constant lazy propagation: store the sequence state

**Reference:** CF 446C — DZY Loves Fibonacci Numbers.

A normal lazy segment tree works when an update adds the same value to every element. For a Fibonacci range update, the value added at position `i` depends on the offset inside the segment.

The reusable idea is:

> When the lazy update evolves by a small recurrence, store the recurrence state at the left boundary of the node.

For a Fibonacci-like sequence

- `G1 = a`
- `G2 = b`
- `Gk = G(k-1) + G(k-2)`

we have

`Gk = a * F(k-2) + b * F(k-1)` for `k >= 2`.

The sum of the first `len` terms is

`a * F(len) + b * (F(len+1) - 1)`.

So a lazy tag can be the pair `(a,b)`.

If the left child has length `L`, the right child receives the shifted pair

- `G(L+1)`
- `G(L+2)`.

**Complexity:** `O((n + q) log n)`.

**Recognition rule:** if a range update is generated by a fixed-order linear recurrence, try to store only the recurrence state instead of every update value.

## 2. Segment tree over states instead of array positions

**Reference:** CF 1601C — Optimal Insertion.

Sometimes the natural state space is not the elements themselves. In Optimal Insertion, each possible insertion gap `0..n` is a state, and inserting a value `x` into gap `g` has a cost that changes as `x` crosses values of `a`.

For each `a[i]`:

- if `a[i] > x`, it contributes `+1` to gaps `[i,n]`
- if `a[i] = x`, it contributes `0`
- if `a[i] < x`, it contributes `+1` to gaps `[0,i-1]`

Process inserted values in sorted order. As `x` increases past an `a[i]`, update ranges rather than recomputing all gaps.

Store the minimum current cost over all gaps in a lazy segment tree.

**Complexity:** `O((n+m) log n)` after sorting, plus inversion counting of the original array.

**Recognition rule:** if an optimization chooses one of many positions/states and each event changes a contiguous set of states, a range-add/range-min segment tree is often suitable.

## 3. Candidate compression for range queries

**Reference:** CF 1665E — MinimizOR.

If values are below `2^k`, the minimum pairwise OR is achieved by two of the smallest `k+1` values.

For `a[i] < 2^30`, only the smallest `31` values of a range matter.

A segment-tree node therefore stores a sorted list of at most `31` values. Merging two nodes means merging two sorted lists and truncating to `31`.

Each query then brute-forces at most `31 choose 2` pairs.

**Complexity:**

- build: `O(31 n)` up to constant-factor merge cost
- query: `O(31 log n + 31^2)`
- memory: `O(31 n)`

**Recognition rule:** when the domain has a tiny structural parameter such as bit width, try to prove that only `O(parameter)` extreme candidates can matter.

## 4. Coordinate compression: preserve combinatorial changes, not distances

Useful when coordinates are huge but only a small set of boundaries can change the answer.

Typical interval compression uses

- `l`
- `r+1`

for each inclusive interval `[l,r]`.

Consecutive compressed coordinates represent an atomic strip on which membership in every input interval is identical.

A strip `[x[i], x[i+1])` has weight/length `x[i+1]-x[i]`.

This is stronger than merely replacing coordinates by ranks: when lengths matter, preserve the gap size as a weight.

**Reference:** CF 1198E — Rectangle Painting 2.

**Recognition rule:** if `n` or coordinates are enormous but the number of intervals/rectangles is small, compress all boundaries where behavior can change.

## 5. Ordered disjoint intervals + global offsets

**Reference:** CF 1638E — Colorful Operations.

Maintain maximal color segments in an ordered map keyed by left endpoint.

Useful operations:

1. `split(pos)` — ensure an interval begins at `pos`.
2. Recolor `[l,r]` — split at `l` and `r+1`, iterate affected segments, then erase/merge.
3. Global update per color — keep a separate `add[color]` instead of touching every segment of that color.

If values must stay unchanged during recoloring from `old` to `new`, compensate the base value by

`add[old] - add[new]`.

With a Fenwick tree supporting range add / point query:

`actual[i] = base[i] + add[color[i]]`.

**Recognition rule:** if updates change colors/labels on intervals and another operation affects every item of one label, separate structural interval changes from global per-label offsets.

## 6. Digit DP that returns both count and sum

**Reference:** CF 1073E — Segment Sum.

When the question asks for the sum of all valid numbers, a digit-DP state should often return

- `cnt`: number of valid completions
- `sum`: sum of valid completions

When placing digit `d` with `rem` digits after it:

`new_sum += child.sum + child.cnt * d * 10^rem`.

A mask can track used digits. Leading zeros can be represented by keeping `mask = 0` until a nonzero digit is chosen.

For a range `[L,R]`, solve as

`solve(R) - solve(L-1)`.

**Complexity:** typically `O(number_of_digits * 2^10 * 10 * small_flags)`.

**Recognition rule:** if a digit DP asks for aggregate values rather than counts, enrich each state with the sufficient statistics needed to combine children.

## 7. DSU + maximum spanning forest from a deletion problem

**Reference:** CF 1408E — Avoid Rainbow Cycles.

A set-element membership can be modeled as an edge in a bipartite incidence graph:

- left vertices = sets
- right vertices = elements
- membership = edge

The forbidden rainbow-cycle condition becomes ordinary acyclicity in the incidence graph.

If deleting a membership edge has cost `w`, minimizing deleted cost is equivalent to maximizing the total weight of edges kept subject to being a forest.

That is exactly a **maximum spanning forest**.

Algorithm: sort edges descending and run Kruskal with DSU.

`answer = total_weight - maximum_spanning_forest_weight`.

**Complexity:** `O(E log E)`.

**Recognition rule:** if you must delete minimum-weight edges so the remaining graph is acyclic, immediately think `total - maximum spanning forest`.

## 8. Bipartite matching, vertex cover, and independent set

Core identities:

- A **matching** is a set of edges sharing no endpoints.
- A **vertex cover** selects vertices touching every edge.
- An **independent set** selects vertices with no edge between selected vertices.

For every graph:

`maximum independent set size + minimum vertex cover size = |V|`.

For bipartite graphs, Kőnig's theorem gives

`minimum vertex cover size = maximum matching size`.

Therefore for bipartite graphs:

`maximum independent set size = |V| - maximum matching size`.

**Reference:** CF 1389F — Bicolored Segments.

### Kuhn algorithm

Try to augment from every left vertex with DFS. A failed DFS may recursively relocate already matched left vertices.

General worst-case complexity: `O(VE)`.

### Hopcroft–Karp

Build layers of shortest augmenting paths and augment many paths per phase.

Complexity: `O(E sqrt(V))`.

**Recognition rule:** if conflicts only exist between two categories, inspect whether the conflict graph is bipartite and whether the objective is an independent set / vertex cover / matching variant.

## 9. Offline reverse processing + incremental matching

**Reference:** CF 1139E — Maximize Mex.

Forward deletions are hard. Reverse time so deletions become insertions.

Model each student as an edge

`potential -> club`.

To have mex at least `k`, every potential `0..k-1` must be matched to a distinct club.

Maintain a matching while edges are inserted in reverse order. After each insertion, repeatedly try to augment the current `mex` value.

Each successful augmentation increments `mex`.

**Recognition rule:** if a dynamic problem only deletes objects, reverse the timeline and ask whether the insertion-only version has a monotone invariant you can maintain.

## 10. Components with `E <= V`: tree vs unicyclic reasoning

**Reference:** CF 1027F — Session in BSU.

Each exam chooses one of two possible days. Model:

- day = vertex
- exam = edge between its two candidate days

Each vertex can be chosen by at most one incident edge.

For a connected component:

- `E > V`: impossible
- `E = V`: unicyclic; every vertex must be used
- `E = V-1`: tree; exactly one vertex may remain unused

For the minimax objective in that problem, a tree can leave its largest day unused, so the component contribution is its second-largest day.

**Recognition rule:** when each object chooses one of two resources and every resource has capacity one, the object-resource relation may be more naturally viewed as an ordinary graph edge rather than a bipartite graph.

## 11. Reverse BFS for minimax / adversarial edge-label choices

**Reference:** CF 1407E — Egor in the Republic of Dagestan.

Reverse BFS from the target can solve problems where each vertex chooses one of two edge classes and an adversary/optimization depends on the worst class.

For each vertex `u`, track whether a reachable successor has been seen through each edge type.

The first discovered successor of a type gives the minimum reachable distance using that type. Once both types are known, the vertex's forced finite distance is determined by the worse of the two minima.

Processing vertices in BFS order makes the second type discovered correspond to the larger of the two minima.

**Recognition rule:** if a shortest-path problem has local binary choices and an adversarial max/min structure, reversing edges and propagating when all required categories become known can avoid explicit game DP.

## 12. k-core peeling + small-candidate verification

**Reference:** CF 1439B — Graph Subset Problem.

Repeatedly remove vertices of degree `< k`.

- if vertices survive, they form a valid `k`-core solution
- when removing a vertex with current degree `k-1`, `{v} + current_neighbors(v)` has exactly `k` vertices and is the only local clique candidate worth testing there

If a `k`-clique can exist, then

`k(k-1)/2 <= m`,

so `k = O(sqrt(m))`.

This makes an `O(k^2)` clique check acceptable.

Prefer sorted adjacency vectors + `binary_search` when the graph is static; they are often faster and more memory-efficient than `unordered_set` because of cache locality and lower allocation overhead.

**Recognition rule:** peeling often exposes exactly-sized local candidates, and density bounds can prove those candidates are small enough to brute-force.

## 13. FFT / convolution for all alignments at once

**Reference:** CF 528D — Fuzzy Search.

Convolution:

`C[k] = sum_i A[i] * B[k-i]`.

Equivalently:

`C[i+j] += A[i] * B[j]`.

To compute sliding dot products of text `A` against pattern `P`, reverse the pattern:

`B[j] = P[m-1-j]`.

Then alignment starting at `s` is stored at

`C[s+m-1]`.

For fuzzy DNA matching, build one binary text array per character indicating whether that character exists within distance `k` of each text position. Convolve with the reversed pattern indicator for that character, sum over `A/C/G/T`, and an alignment is valid if the total equals pattern length.

**Complexity:** `O((n+m) log(n+m))` per constant number of convolutions.

**Recognition rule:** if you need the same dot-product-like comparison for every shift, convolution is the standard acceleration from `O(nm)` to about `O(n log n)`.

## 14. Min-cut as a binary-state cost model

The most reusable interpretation of a directed cut is:

For an edge

`u --c--> v`

we pay `c` exactly when

- `u` is on the source side
- `v` is on the sink side

This gives a tiny language for modeling binary decisions.

Assume source side = selected/TRUE and sink side = unselected/FALSE.

### Positive profit

`source --p--> X`

If `X` is rejected, the edge is cut and we lose `p`.

### Selection cost

`X --c--> sink`

If `X` is selected, the edge is cut and we pay `c`.

### Hard dependency

`A --INF--> B`

Forbids `A = selected, B = unselected`.

So it encodes

`A => B`.

### Soft dependency / penalty

`A --c--> B`

Allows `A = selected, B = unselected`, but charges penalty `c`.

This distinction is important:

- `INF` = forbidden state
- finite capacity = allowed state with a price

## 15. Maximum-weight closure

**Reference:** CF 1082G — Petya and Graph; CF 2026E — Best Subsequence.

A common form is:

- selecting object `X` gives profit `+p`
- selecting object `Y` costs `c`
- selecting `X` requires selecting `Y`

Build

- `source -> X` with capacity `p`
- `Y -> sink` with capacity `c`
- `X -> Y` with capacity `INF`

Let `P` be the sum of all positive profits.

Then

`answer = P - mincut`.

Why: the cut minimizes

`lost profits from rejected positive objects + costs of selected negative objects`.

### Best Subsequence pattern

- each selected number gives `+1`
- selecting a number forces every set bit in that number to be selected
- each selected bit costs `1`

Graph:

- `source -> number` capacity `1`
- `number -> bit` capacity `INF` if the bit is set
- `bit -> sink` capacity `1`

Then

`answer = n - mincut`.

**Recognition rule:** "choose profitable objects, pay for required resources" is one of the strongest signals for maximum closure / min-cut.

## 16. Binary-state min-cut, not just selected/unselected

**Reference:** CF 311E — Biologist.

A cut side can represent any two states, for example:

- source side = state `0`
- sink side = state `1`

If a dog starts in state `0` and flipping to `1` costs `v`:

`source -> dog` capacity `v`.

If a dog starts in state `1` and flipping to `0` costs `v`:

`dog -> sink` capacity `v`.

A person who gains reward `w` only if all listed dogs are `0` can be modeled with a person node `P`:

- `source -> P` capacity `w`
- `P -> dog` capacity `INF` for every required dog

A person requiring all listed dogs to be `1` uses reversed dependency orientation:

- `dog -> P` capacity `INF`
- `P -> sink` capacity `w`

The direction changes because state `0` and state `1` live on opposite sides of the cut.

**Recognition rule:** min-cut is fundamentally a two-label optimization framework. "selected/not selected" is only one interpretation.

## 17. Segment-tree DP over intervals

**Reference:** CF 1557D — Ezzat and Grid.

For each row, compute the best chain ending there. If row `i` has intervals, query the maximum DP value over all covered coordinates, store the predecessor row, then range-update all intervals of row `i` with its new DP value.

The important ordering is:

1. query all intervals of the current object
2. decide `dp[i]`
3. update all intervals

This prevents an object from using itself during the same transition.

Coordinate-compress interval endpoints to make the segment tree feasible.

**Recognition rule:** if transitions depend on whether intervals overlap, coordinate compression + range maximum can turn an `O(n^2)` DP into `O(m log m)`.

## Practical checklist

When a new problem feels difficult, ask:

1. Is there a small structural parameter (bits, alphabet size, recurrence order) that can bound the important state?
2. Can deletions be reversed into insertions?
3. Can a forbidden structure be reframed as a forest, matching, cover, or core?
4. Are coordinates huge but only interval boundaries matter?
5. Is every decision binary? If yes, can a cut side represent the two states?
6. Does selecting one thing force another? Try maximum closure/min-cut.
7. Do I need all shift alignments? Try convolution.
8. Are updates changing contiguous sets of states? Try a lazy segment tree over the state space rather than the input array.
